# map4child

Прототип выбора детских занятий в Москве: карта и список, прежние фильтры по столбцам таблицы — специальность, тип партнёра, массовость, частный/государственный и район. Можно выбрать несколько значений: внутри фильтра действует «ИЛИ», между фильтрами — «И». Для площадок с заполненными группами дополнительно доступны возраст, дни, время и цена, карточки программ, запись на пробное и отзывы после подтверждения посещения. Данные родителя, записи и отзывы сохраняются только в LocalStorage. Центры их не получают; оплаты и регистрации нет. Интерфейс работает на компьютере и телефоне.

По умолчанию показан весь каталог, включая восемь вымышленных демонстрационных площадок с доступной записью. Включите «Можно записаться», чтобы оставить площадки со свободными сеансами. Команда готовит данные через [форму Google Sheets](docs/editor-guide.md); сайт обновляется только ручным workflow. Требования: [спецификация MVP](docs/mvp-spec.md), результаты и ограничения: [отчёт MVP](docs/mvp-validation.md).

Над картой находится селектор **OpenStreetMap / Яндекс Карты**, в шапке — переключатель светлой, тёмной и системной темы. По умолчанию открываются Яндекс Карты и используется системная тема. Сохранённый в браузере выбор имеет приоритет. При ошибке загрузки Яндекса автоматически включается OSM с уведомлением; она остаётся выбранной и после перезагрузки. Яндекс можно повторно выбрать вручную.

React + TypeScript + Vite, компоненты и темы Gravity UI UIKit. Карты: Leaflet с OpenStreetMap и `leaflet.markercluster`, либо Яндекс Карты JS API v3 с официальным кластеризатором. Каталог готовится из Google Sheets во время сборки; браузер получает только итоговые публичные данные. [Согласованные правила](docs/design.md), [словарь](GLOSSARY.md), [аудит источника](docs/source-data-audit.md).

## Интерфейс и карты

- [Gravity UI UIKit](https://github.com/gravity-ui/uikit) задаёт тему приложения и компоненты состояний карты. Основной интерфейс MVP использует нативные поля, кнопки и модальные `dialog`, стилизованные в `src/styles.css`.
- Обе карты используют один каталог и общую фильтрацию. Дополнительная подготовка данных и повторное геокодирование не нужны: Leaflet получает `[latitude, longitude]`, Яндекс — `[longitude, latitude]`. Кластеризаторы могут по-разному группировать соседние точки; карточки, цвета и количество точек совпадают.
- OSM работает без ключа, используя [Leaflet 1.9.4](https://leafletjs.com/reference-1.9.4.html), [markercluster](https://github.com/Leaflet/Leaflet.markercluster) и тайлы `https://tile.openstreetmap.org/{z}/{x}/{y}.png`. Атрибуция видна на карте, загрузка идёт только для текущего вида, офлайн-скачивания и предзагрузки нет. Соблюдается обычное HTTP-кэширование браузера. При изменении способа загрузки учитывайте [политику сервера тайлов OSM](https://operations.osmfoundation.org/policies/tiles/).
- В тёмной теме к растровой подложке OSM применяется CSS-фильтр; у Яндекса используется тема SDK. Смена темы не меняет данные и фильтры.
- SDK Яндекса загружается, когда активен Яндекс — по умолчанию или после ручного выбора. При сохранённом выборе OSM скрипт Яндекса не загружается. Любой отказ загрузки, включая `403`, отсутствие ключа и тайм-аут, переводит карту на OSM. Обработчик ошибки внешнего скрипта не получает HTTP-статус; ответ Яндекса без CORS не позволяет надёжно выделить только `403`. Причина и этап выводятся в Console без ключа, HTTP-ответ проверяется в Network. При недоступности самой OSM остаются список площадок, карточки и повторная попытка.

## Настройка с нуля

Пройдите шаги по порядку: [локальный запуск](#1-локальный-запуск) → [Яндекс Карты](#2-ключ-яндекс-карт) → [Google Sheets](#3-доступ-к-google-sheets) → [публикация](#github-actions-и-pages). Для проверки интерфейса достаточно первого шага. Если настройка не сработала, смотрите [частые ошибки](#частые-ошибки).

Понадобятся Node.js 24 с npm, аккаунт Google и право поделиться исходной таблицей. Аккаунт и ключ Яндекса нужны только для Яндекс Карт: для OSM шаг 2 можно пропустить. Для публикации нужен доступ к настройкам репозитория `dpolyakov/map4child`.

### 1. Локальный запуск

Все команды выполняйте из каталога `map4child`, где лежит `package.json`.

```sh
node --version
npm ci
```

Первая команда должна показать `v24.x.x`. Зависимости зафиксированы в `package-lock.json`; `.npmrc` выбирает публичный `registry.npmjs.org` для одинаковой установки локально и в Actions.

Создайте `.env` из шаблона, если файла ещё нет; существующие настройки команда сохранит:

```sh
test -f .env || cp .env.example .env
mkdir -p .local
```

На следующих шагах заполните `.env`. Ниже пример структуры; вместо заглушек вставьте свои значения:

```dotenv
# Необязательно: для OSM оставьте пустым.
VITE_YANDEX_MAPS_API_KEY=
GOOGLE_SHEET_URL=https://docs.google.com/spreadsheets/d/ID_ВАШЕЙ_ТАБЛИЦЫ/edit
GOOGLE_APPLICATION_CREDENTIALS=.local/google-service-account.json
```

Vite и скрипты читают `.env`, затем необязательный `.env.local` с локальными переопределениями; переменные окружения имеют приоритет. `.env`, `.env.local` и `.local/` исключены из Git. JSON Google храните в `.local/`.

Для первого запуска без доступа к сервисам:

```sh
npm run data:demo
npm run dev -- --port 4173
```

Откройте [локальный сайт](http://127.0.0.1:4173/map4child/). Если порт занят, Vite выведет другой адрес в терминале. Без API-ключа приложение автоматически перейдёт на OSM и покажет вымышленные точки; в интерфейсе будет отметка деморежима. Нажмите метку, проверьте карточку и фильтры. Для подложки нужен интернет. Остановка сервера: `Ctrl+C`.

### 2. Ключ Яндекс Карт

1. Войдите в [Кабинет разработчика Яндекса](https://developer.tech.yandex.ru/).
2. Получите ключ для пакета **JavaScript API**. Скопируйте значение ключа в `VITE_YANDEX_MAPS_API_KEY` в `.env`.
3. В кабинете откройте этот ключ, нажмите **Изменить** и заполните **Ограничение по HTTP Referer**. Это обязательная настройка для API v3.
4. Добавьте следующие значения, каждое на отдельной строке, без `http://`, порта и пути:

   ```text
   127.0.0.1
   localhost
   dpolyakov.github.io
   ```

5. Сохраните настройки. Активация ключа и изменение ограничений могут занять до 15 минут.
6. Перезапустите `npm run dev -- --port 4173` и обновите страницу целиком.

Выберите «Яндекс Карты» в шапке. При действующем ключе появится подложка Яндекса с теми же точками; при отказе снова включится OSM и появится уведомление. Ключ входит в браузерную сборку; доступ по доменам ограничивается настройками Яндекса. [Получение ключа](https://yandex.ru/maps-api/docs/js-api/common/quickstart.html), [правила HTTP Referer](https://yandex.ru/maps-api/docs/js-api/limit.html).

### Поиск адреса

Для поиска по адресу нужен активированный HTTP Геокодер. Укажите его ключ в `VITE_YANDEX_GEOCODER_API_KEY` локально и в одноимённой repository variable GitHub. Если отдельного ключа нет, приложение пробует ключ карты; он должен иметь доступ к Геокодеру. Проверка 11 ноября 2026 вернула `403 Invalid api key`: для текущего ключа поиск адреса пока не подтверждён.

Запрос выполняется только по кнопке на Яндекс Картах. На OSM доступен выбор точки нажатием. При переходе на OSM результат геокодирования сбрасывается; сохранённые координаты Геокодера удаляются при чтении спустя 30 дней. [Формат API](https://yandex.ru/maps-api/docs/geocoder-api/response.html).

### 3. Доступ к Google Sheets

Сервисный аккаунт читает закрытую таблицу при сборке. Посетителям сайта вход в Google не нужен.

**Создайте проект и включите API:**

1. Откройте [Google Cloud Console](https://console.cloud.google.com/).
2. В выборе проекта сверху выберите существующий проект или **New project**, задайте имя, например `map4child`, и создайте проект.
3. Откройте **APIs & Services → Library**, найдите **Google Sheets API** и нажмите **Enable**. Убедитесь, что выбран нужный проект. [Инструкция Google](https://developers.google.com/workspace/guides/enable-apis).

**Создайте сервисный аккаунт и скачайте JSON:**

1. Откройте **IAM & Admin → Service Accounts → Create service account**.
2. Укажите имя, например `map4child-reader`, и завершите создание. Роли доступа к ресурсам Cloud для чтения этой таблицы не требуются.
3. Откройте созданный аккаунт и скопируйте его email вида `map4child-reader@PROJECT_ID.iam.gserviceaccount.com`.
4. Перейдите в **Keys → Add key → Create new key → JSON → Create**. Браузер скачает файл.
5. Переместите скачанный файл в каталог проекта `.local/` и переименуйте в `google-service-account.json`. В `.env` укажите `GOOGLE_APPLICATION_CREDENTIALS=.local/google-service-account.json`. Это путь к файлу; сам JSON в эту переменную вставлять не нужно.

**Разрешите чтение таблицы:**

1. Откройте исходную Google-таблицу и нажмите **Настройки доступа / Share**.
2. Добавьте email сервисного аккаунта с ролью **Читатель / Viewer**.
3. Снимите **Уведомить пользователей / Notify people** и сохраните доступ. Настройку общего доступа оставьте **Ограниченный доступ / Restricted**.
4. Скопируйте URL таблицы из адресной строки в `GOOGLE_SHEET_URL` в `.env`.

Доступ выдаётся непосредственно таблице. OAuth consent screen и domain-wide delegation для этого способа подключения не нужны. [Создание аккаунта, JSON-ключа и предоставление доступа](https://developers.google.com/workspace/guides/create-credentials#service-account).

### 4. Проверка настоящих данных

Остановите dev-сервер, затем выполните:

```sh
npm run data:sync
npm run check
npm run build
npm run preview -- --port 4173
```

После успешного импорта появится сообщение `Подготовлено точек: N. Отчёт: .generated/report.md`, где `N` — фактическое число точек. Откройте отчёт и проверьте пропуски, затем [локальный сайт](http://127.0.0.1:4173/map4child/): отметки деморежима быть не должно. Сверьте несколько карточек и фильтров с таблицей.

При ошибке импорта старый локальный каталог удаляется, чтобы случайно не собрать устаревшие данные. Исправьте настройку или данные и повторите `npm run data:sync`. Если нужно вернуться к демонстрации, явно выполните `npm run data:demo` и `npm run dev`.

Обычная `npm run build` запрещает сборку демокаталога. Ключ Яндекса для сборки не обязателен: настоящие данные доступны через OSM. Для сборки демо используйте `npm run build:demo`. После изменения ключа пересоберите сайт: `npm run preview` показывает уже собранный `dist` и сам его не обновляет.

## Правила импорта

URL источника отсутствует в исходном коде. `config/sheets.ts` содержит только разрешённые ID вкладок: их переименование сохраняет связь, а подключение другой таблицы с иными вкладками потребует обновления этого списка. Служебные и новые неразрешённые вкладки не публикуются.

Исходный ответ, подготовленный каталог и отчёт появляются в `.generated/`, которая исключена из Git. Отчёт `.generated/report.md` указывает лист, строку и причину пропуска. Поля редакторов и адреса не входят в итоговый каталог.

### Формат таблицы

Обязательные заголовки: `Название студии`, `Район`, `Тип партнера`, `Массовость`, `Частный или гос`, `Специальность`. Порядок столбцов может различаться. `Координаты` и `Источник`/`Источники` необязательны; для текущего листа ЮЗАО явно поддержаны безымянные I/J. При появлении именованных столбцов используются они.

- Координаты: `широта, долгота`; несколько пар через `;`. Пример: `55.75, 37.60; 55.76, 37.61`.
- Источники: явные HTTP(S)-ссылки в тексте, можно по одной на строку. Произвольные подписи с URL, скрытыми только в форматировании Google Sheets, не входят в контракт импортёра.
- Уникальная точка: название и числовая пара координат, без округления координат. Пробелы по краям названия удаляются; регистр и внутреннее написание сохраняются.
- Одинаковые точки объединяются, их характеристики и ссылки собираются без повторов. При наличии известного значения «Нет данных» из другой дублирующей строки не добавляется.
- `Мульти` — обычная самостоятельная специальность. Только несколько разных специальностей у одной точки дают многоцветную метку.
- Массовость: ровно `Сеть`, `Франшиза` или `Частная`. Любые другие и пустые значения отображаются как `Нет данных`.
- Строки без названия и пригодных координат пропускаются. Из нескольких пар публикуются корректные. Автоматического геокодирования нет.

Изменение обязательной структуры, недоступность источника или ноль итоговых точек останавливают сборку. Предыдущая публикация остаётся доступной.

## GitHub Actions и Pages

Настраивайте публикацию после отправки исходного кода и `.github/workflows/publish.yml` в основную ветку `main`. В пустом репозитории workflow ещё не доступен. Локальный `.env` в GitHub не передаётся: значения нужно добавить отдельно.

### Переменные и секрет

1. В [репозитории dpolyakov/map4child](https://github.com/dpolyakov/map4child) откройте **Settings → Secrets and variables → Actions**.
2. На вкладке **Variables** через **New repository variable** создайте `GOOGLE_SHEET_URL` и, если нужен Яндекс, `VITE_YANDEX_MAPS_API_KEY`.
3. На вкладке **Secrets** нажмите **New repository secret**, укажите имя `GOOGLE_SERVICE_ACCOUNT_JSON` и вставьте полное содержимое скачанного JSON от `{` до `}`. Сохраните переносы строк и поле `private_key`. Нужен сам JSON, без Base64 и без дополнительной пары кавычек вокруг него.

| Где создать | Имя | Что вставить |
|---|---|---|
| Repository variable | `GOOGLE_SHEET_URL` | URL исходной Google-таблицы |
| Repository variable, необязательно | `VITE_YANDEX_MAPS_API_KEY` | Ключ Яндекс Карт; в HTTP Referer должен быть `dpolyakov.github.io`. Для OSM не нужен |
| Repository secret | `GOOGLE_SERVICE_ACCOUNT_JSON` | Полное содержимое `.local/google-service-account.json` |

Секрет нужен на уровне **репозитория**: импорт выполняется в задании `build`, к которому окружение `github-pages` не подключено. Переменная с локальным путём `GOOGLE_APPLICATION_CREDENTIALS` в CI не используется. [Переменные GitHub](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-variables), [секреты GitHub](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets).

### Первая публикация и обновления

1. В **Settings → Pages → Build and deployment** установите **Source: GitHub Actions**. Используется уже подготовленный workflow; создавать новый по шаблону не нужно.
2. Откройте **Actions → Update map → Run workflow**, выберите ветку `main` и запустите.
3. В открывшемся запуске дождитесь успешных заданий `build` и `publish`. В **Summary** будет отчёт импорта с числом точек и причинами пропусков.
4. Убедитесь, что шаг **Deploy the same artifact to Pages** завершился успешно, и откройте адрес из deployment: [dpolyakov.github.io/map4child](https://dpolyakov.github.io/map4child/).
5. Проверьте карту, карточку и фильтр на опубликованном сайте. В репозитории должна появиться ветка `gh-pages` с HTML, JS, CSS и итоговым каталогом.

После редактирования таблицы повторяйте **Run workflow**. Изменения таблицы, переменных и исходного кода сами по себе публикацию не запускают. Статический сайт обновится только после успешной сборки и deploy.

Workflow проверяет код, читает таблицу, собирает сайт, сохраняет только содержимое `dist` в `gh-pages` и публикует тот же артефакт через `deploy-pages`. Обновление запускается вручную. Запуски сериализованы; первая публикация создаёт `gh-pages`, следующие сохраняют историю ветки. Персональный GitHub-токен не требуется.

В `gh-pages` находятся HTML, JS, CSS и финальный публичный каталог — эти данные доступны посетителям сайта. Исходная выгрузка, служебный отчёт, URL исходной таблицы и ключ Google туда не попадают. Google-ключ доступен только шагу импорта.

Push через `GITHUB_TOKEN` не запускает публикацию Pages из ветки, поэтому workflow явно выполняет deploy. Если коммит в `gh-pages` успешен, а deploy завершился ошибкой, ветка может содержать более свежую сборку, чем сайт. Успех оценивайте по шагу deploy. [Документация GitHub](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## Частые ошибки

| Симптом | Что проверить и сделать |
|---|---|
| «Яндекс Карты недоступны», запрос SDK возвращает `403` / `Invalid api key` | OSM включится автоматически. Для Яндекса проверьте значение `VITE_YANDEX_MAPS_API_KEY`, пакет **JavaScript API** и активацию ключа. В HTTP Referer должен быть хост открытой страницы: `127.0.0.1`, `localhost` или `dpolyakov.github.io`. После изменения подождите до 15 минут и снова выберите Яндекс в шапке. После замены ключа в `.env` перезапустите dev-сервер или пересоберите сайт для preview. Если ошибка осталась, обратитесь в поддержку API Яндекса с текстом ответа. |
| Яндекс переключается на OSM, причина неясна | В DevTools → Console найдите `[map4child] Ошибка загрузки Яндекс Карт`. Сообщение содержит этап (SDK, готовность API, React-модуль или кластеризатор), причину и стек; ключ скрывается. Для запроса SDK проверьте HTTP-ответ в Network. Повторный выбор Яндекса запускает новую попытку: неудачная загрузка не кэшируется. |
| «Карта временно недоступна» и список площадок | Проверьте сеть, загрузку JS и запросы к `tile.openstreetmap.org` в DevTools. Ошибка OSM также выводится в Console. После восстановления соединения нажмите «Повторить загрузку карты». |
| После изменения `.env` используется старый ключ | Проверьте переопределения в `.env.local` и окружении терминала. Перезапустите dev-сервер; для `preview` сначала повторите сборку. Для Pages обновите repository variable и запустите workflow. |
| `GOOGLE_SHEET_URL должен содержать URL Google Sheets.` | Вставьте полный HTTPS-адрес вида `https://docs.google.com/spreadsheets/d/ID/edit`, без окружающего текста. |
| `Не удалось полностью прочитать Google Sheets...` | Проверьте наличие JSON по пути `GOOGLE_APPLICATION_CREDENTIALS` относительно каталога запуска. Убедитесь, что в его проекте включён Sheets API, а email из поля `client_email` имеет доступ «Читатель» к нужной таблице. В CI проверьте repository secret `GOOGLE_SERVICE_ACCOUNT_JSON`. |
| `GOOGLE_SERVICE_ACCOUNT_JSON содержит некорректный JSON.` | Повторно скопируйте полное содержимое файла ключа в Secret. Не вставляйте путь к файлу или только значение `private_key`. |
| Google Cloud не разрешает создать JSON-ключ или поделиться таблицей | В организации могут действовать ограничения на ключи сервисных аккаунтов и внешний доступ. Уточните разрешённый способ у администратора; текущий workflow рассчитан на JSON-ключ и прямой доступ сервисного аккаунта к таблице. |
| Отсутствует согласованный лист, обязательный столбец или нет итоговых точек | Сверьте `config/sheets.ts`, заголовки и формат координат с разделом «Правила импорта». Если `.generated/report.md` создан, прочитайте причины пропусков. Исправьте данные и повторите импорт. |
| Нет кнопки `Run workflow` | Проверьте, что workflow уже находится в основной ветке репозитория, GitHub Actions включены и у вас есть право запускать workflow. |
| Сборка прошла, но Pages не опубликован | Проверьте **Source: GitHub Actions** и лог задания `publish`. Если окружение `github-pages` требует согласования, выполните его в интерфейсе GitHub. Успешного задания `build` недостаточно: должен завершиться deploy. |

После исправления повторите именно неудачный этап: импорт, сборку, загрузку страницы или workflow. Сообщение `.env.local not found. Continuing without it.` допустимо, если настройки хранятся в `.env`.

`localhost` и `127.0.0.1` различаются при проверке HTTP Referer. Если в кабинете разрешён только `localhost`, открывайте `http://localhost:4173/map4child/`, даже когда Vite выводит адрес с `127.0.0.1`. Порт должен совпадать с портом запущенного сервера.

## Проверки

Для MVP `npm run check` также проверяет соответствие одной группы всем фильтрам, расписание, места, отмены, посещения, отзывы, снимки истории, разделение черновика и подготовленной версии, конфликты редактора. `npm run editor:build` собирает Apps Script. Установка редактора и добавление фото по ссылке описаны в [руководстве](docs/editor-guide.md), текущая готовность — в [отчёте MVP](docs/mvp-validation.md).

`npm run check` проверяет типы и тестирует импорт, enum-значения, несколько координат, объединение точек, ошибочные строки, правила фильтрации и порядок координат для SDK. `npm run build` дополнительно проверяет каталог и состав `dist`.

Тесты используют только синтетические записи. Импорт Google Sheets проверен 3 ноября 2026 года; 4 ноября проверены живая OSM на каталоге из 1615 точек, Gravity UI и переход на OSM при отказе SDK Яндекса. Позже в том же прогоне Яндекс успешно загрузился без замены ключа; проверены переключение в обе стороны и обе темы. Причина прежнего `403` не установлена. Первый workflow и публикация Pages успешно выполнены 4 ноября; после восстановления Яндекса он выбран провайдером по умолчанию. Результаты и границы проверки описаны в [отчёте](docs/validation.md). Старый `example.html` остаётся локальным визуальным образцом и исключён из Git из-за встроенного набора данных.
