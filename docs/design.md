# Договорённости по map4child

Обновлено 4 ноября 2026 года. Статус: требования Q1–Q16 и архитектура согласованы, код опубликован в публичном репозитории; первая публикация Pages выполнена 4 ноября. [Результаты проверки](validation.md).

## Согласовано

- По последнему уточнению от 4 ноября, после восстановления доступа, frontend по умолчанию показывает Яндекс Карты; селектор OSM / Яндекс Карты расположен в шапке. Обе реализации поддерживают метки, кластеризацию, цвет по специальности и карточки точек. Сохранённый выбор имеет приоритет над значением по умолчанию. Ошибка загрузки Яндекса, включая `403`, включает OSM с уведомлением и сохраняет её для следующего открытия. Повторная попытка — снова выбрать Яндекс.
- По запросу от 4 ноября элементы интерфейса и темы переведены на Gravity UI UIKit. Для компоновки используется `Flex`; page-constructor не требуется для одного экрана карты и не подключён.
- На карте показываются [точки площадок](../GLOSSARY.md). По уточнению после Q10 уникальная точка — связка «название + пара координат»; адрес не участвует в определении уникальности. Каждая пара координат в записи создаёт отдельную точку с данными этой записи. Разные названия при одинаковых координатах остаются разными точками.
- Строки с одинаковыми названием и координатами объединяются в одну точку. Специальности, остальные характеристики и ссылки собираются как уникальные значения. Согласовано в Q11.
- Карта и выбранные поля публичны; граница публикации описана в [ADR-0001](adr/0001-public-map-data.md). Согласовано в Q1.
- Источник данных — Google-таблица. GitHub Actions читает её, сохраняет данные на диск, собирает frontend и публикует артефакт на GitHub Pages.
- В первой версии обновление запускается вручную через Run workflow. При ошибке чтения или сборки новая версия не публикуется, предыдущая остаётся доступной. Согласовано в Q3; отсутствие координат отдельно разрешено в Q6 как причина пропустить запись.
- Поддерживаются компьютер и телефон. На компьютере фильтры слева, на телефоне открываются кнопкой поверх карты; карточка доступна на обоих экранах. Согласовано в Q4.
- Исходные данные остаются на нескольких листах и приводятся к общей структуре при сборке. Используется явный список всех пяти текущих листов с данными: Пресненский, Хамовники, Хорошево-Мневники, ЮЗАО, Коммунарка; служебный «Промпт» исключён. Новая вкладка автоматически не публикуется. Согласовано в Q5–Q6.
- Записи без координат пропускаются при публикации; остальные могут быть опубликованы. Подготовку координат пользователь поручает отдельному агенту. Автоматическое геокодирование в map4child не требуется. Согласовано в Q6.
- Карточка содержит название, специальность, тип партнёра, массовость и признак «частный/государственный». Район используется как фильтр, в карточке не отображается. Источник преобразуется в блок ссылок, открывающихся с `target="_blank"`. Согласовано в Q7.
- Одна специальность — одноцветная метка; несколько — многоцветная. Кластер нейтральный, число означает количество точек, а не занятий или исходных строк. При приближении кластер раскрывается; для совпадающих координат доступен список точек. Согласовано в Q8 и уточнено правилом уникальности после Q10.
- «Мульти» — самостоятельная категория специальности с собственным цветом и пунктом фильтра. Точка только с категорией «Мульти» имеет одноцветную метку; многоцветная метка используется, когда у точки действительно несколько разных специальностей. Уточнение к Q12.
- Фильтры: специальность, тип партнёра, массовость, частный/государственный и район; поиск — по названию. Внутри фильтра действует ИЛИ, между фильтрами — И; пустой выбор означает «все». Для многозначного поля достаточно совпадения одного значения. Согласовано в Q14.
- `example.html` служил визуальным ориентиром для общей компоновки, поиска и карточек (Q9). Текущие компоненты — Gravity UI; источник актуальных данных — Google-таблица.
- Уточнение от 4 ноября: переключатель «Как в системе / Светлая / Тёмная». По умолчанию используется системная тема, явный выбор сохраняется в браузере. Тема интерфейса и подложки карты совпадает. Ошибки загрузки Яндекс Карт выводятся в консоль с причиной и без ключа; доступна повторная попытка без перезагрузки страницы.
- Целевой репозиторий — публичный `dpolyakov/map4child`. URL Google-таблицы передаётся через CI-переменную; её предлагаемое имя — `GOOGLE_SHEET_URL`. Готовый сайт коммитится в `gh-pages`; исходные и предобработанные промежуточные данные в Git не попадают. Согласовано в Q10. Финальные данные, необходимые карте, входят в публичную сборку.
- Доступ к Google-таблице — через сервисный аккаунт с правом «Читатель»; его ключ хранится в GitHub Secret. Настройка доступа и ключа Яндекс Карт выполняется при реализации. Согласовано в Q16.

## Нормализация и ошибки данных

Специальности приводятся к согласованным категориям:

| Значения источника | Категория |
|---|---|
| `Спорт`, `спорт` | Спорт |
| `ИТ/инженеры`, `ИТ` | ИТ и инженерия |
| `Творчество/искусство`, `Творчество/исскуство`, `творчество и искусство` | Творчество и искусство |
| `Наука`, `наука` | Наука |
| `Иностранные языки` | Иностранные языки |
| `Мульти`, `мульти` | Мульти |

Неизвестные значения специальности сохраняются как отдельные категории с нейтральным цветом. «Мульти» участвует в фильтрации наравне с остальными категориями. Согласовано в Q12 с уточнением пользователя.

Для «Массовости» действуют точные значения enum: `Сеть | Франшиза | Частная`. Пустая ячейка и любое значение вне enum отображаются как «Нет данных». Ручные варианты не преобразуются в предполагаемые категории: например, `частная студия` и `одиночное учреждение` дают «Нет данных». Значение `Частная` сохраняется с исходным названием. Уточнение пользователя к Q13.

Отсутствующие или некорректные координаты пропускаются; если в записи несколько пар, корректные используются. Запись без названия пропускается. Отчёт сборки содержит лист, номер строки и причину пропуска. Если итоговых точек ноль, таблица недоступна или структура листа перестала распознаваться, публикация останавливается, предыдущий сайт остаётся доступным. Согласовано в Q15. Известное отсутствие столбца координат на части листов рассматривается как отсутствие координат, а не как неожиданная структура.

## Публикация через gh-pages

По [документации GitHub](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site#troubleshooting-publishing-from-a-branch) push через `GITHUB_TOKEN` сам по себе не запускает Pages build. Предлагаемая реализация согласованного результата: сохранить сборку в `gh-pages`, затем в том же workflow передать этот же каталог в `upload-pages-artifact` и выполнить `deploy-pages`; Pages Source — GitHub Actions. Это сохраняет требуемый коммит в ветке и явно выполняет публикацию без отдельного персонального токена. [Официальный workflow](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

Если commit/push завершился, а deploy упал, содержимое `gh-pages` может оказаться новее опубликованного сайта. Успех публикации определяется результатом deploy, а не только наличием коммита. Первый workflow успешно выполнил импорт, сборку, коммит в `gh-pages` и deploy 4 ноября.

## Архитектура и проверка

1. Frontend на React 18 и TypeScript с Vite и Gravity UI UIKit 8. OSM отображается через Leaflet 1.9.4 и markercluster 1.5.3; Яндекс использует API v3, reactify и официальный кластеризатор. Реализации загружаются по выбору через динамический импорт и получают общий отфильтрованный каталог. Предобработка едина: меняется только порядок координат при передаче SDK. Ошибка загрузки Яндекса вызывает переход на OSM: обработчик внешнего скрипта не раскрывает HTTP-статус, поэтому fallback применяется ко всем отказам загрузки. При недоступности OSM сохраняются фильтры, список площадок и карточки. Для тёмной темы растровые тайлы OSM адаптируются CSS-фильтром, Яндекс использует тему SDK.
2. Реализовать чтение выбранных листов, обработку координат, объединение точек и нормализацию полей. Проверить на синтетических примерах несколько координат, совпадения между листами, разные названия в одной позиции, enum «Массовости», самостоятельную категорию «Мульти» и ошибки отдельных записей.
3. Настроить ручной workflow: чтение Google Sheets, временные данные, сборка, коммит только готового сайта в `gh-pages`, публикация Pages. Проверить, что исходная выгрузка, промежуточные файлы, URL таблицы и ключ сервисного аккаунта отсутствуют в Git и публичной сборке. Финальные разрешённые данные карты входят в сборку.
4. Создать публичный `dpolyakov/map4child`, настроить переменную, секреты и Pages, выполнить запуск. Проверить отдельно успешность workflow и работу опубликованного сайта. Если доступы ещё не настроены, явно отделить локальные проверки от непроверенной загрузки Sheets и публикации.

Критерии завершения публикации: сайт показывает точки из согласованных листов, выполняет правила фильтрации и отображения, обновляется ручным workflow и сохраняет предыдущую публикацию при оговорённых ошибках. Фактическая структура источника — в [аудите данных](source-data-audit.md). Локальный запуск и настройка доступов описаны в [README](../README.md).
