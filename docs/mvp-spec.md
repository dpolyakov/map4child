# Спецификация прототипа маркетплейса детских занятий map4child

Дата: 11 ноября 2026 года. Статус: подтверждена пользователем; сайт опубликован, файлы редактора установлены в Apps Script. Полная приёмка ожидает авторизации редактора и подключения HTTP Геокодера; подробности в [отчёте проверки](mvp-validation.md).

Документ задаёт поведение сайта, редактора каталога и публикации, а также критерии приёмки. Он дополняет [договорённости исходной карты](design.md). Описанные здесь изменения — требования к следующей версии; остальные правила исходного проекта сохраняются. Номера Q относятся к интервью о MVP, а не к вопросам в design.md.

## 1. Цель и границы

Родитель ребёнка 8–11 лет в Москве должен найти подходящее регулярное занятие, выбрать группу и дату пробного посещения, проверить условия и получить демонстрационную запись. Затем он может увидеть запись в профиле, отменить её и оставить отзыв после подтверждения посещения.

Команда без навыков разработки должна заполнять карточки через форму внутри Google Sheets. Готовые изменения публикуются ручным запуском GitHub Actions.

| Решение | Требование |
|---|---|
| Формат продукта | Самостоятельный интерактивный прототип на основе map4child |
| Аудитория | Родители детей 8–11 лет в Москве, выбирающие или меняющие регулярное занятие |
| Интерфейс | Компоновка и поведение в духе Яндекс Карт; собственное название map4child |
| Каталог | Текущая Google-таблица с дополнительными столбцами в существующих листах |
| Редактор | Форма Apps Script внутри Google Sheets, работа с компьютера |
| Пользовательские данные | LocalStorage браузера: контактные данные, записи, отзывы, сохранённые точки поиска |
| Публикация | Статическая сборка на GitHub Pages; ручной запуск существующего workflow |
| Реальные действия | Записи, отмены и подтверждения посещений имитируются локально; центры их не получают |
| Разработка | Пользователь и Codex; существующий репозиторий dpolyakov/map4child |
| Срок | Желательный ориентир — 15 ноября 2026 года; это цель, а не результат оценки трудоёмкости |

Новый интерфейс после проверки заменяет текущий [сайт map4child](https://dpolyakov.github.io/map4child/). Предыдущая реализация сохраняется в истории Git. Собственный сервер приложения не требуется; код редактора выполняется в Google Apps Script.

Основание: Q1–Q4, Q17, Q30 и выбор формы внутри Google Sheets вместо Pages CMS.

## 2. Каталог и основные объекты

| Объект | Смысл и обязательные сведения для полного демонстрационного сценария |
|---|---|
| Площадка | Один филиал по одному физическому адресу: постоянный ID, название, адрес, координаты, описание, фотографии, список занятий, состояние публикации, признак демонстрационных данных |
| Занятие | Программа площадки: ID, название, направление, описание программы и формата, сведения о преподавателе, группы |
| Группа | ID, принадлежность к занятию, возрастной диапазон, недельное расписание, длительность, цена пробного посещения, стоимость и условия абонементов, число пробных мест на каждый сеанс, активность |
| Сеанс | Конкретная дата и время занятия группы, полученные из её недельного расписания |
| Запись | Локальная запись одного ребёнка на один пробный сеанс; данные родителя и условия на момент записи |
| Посещение | Отдельно подтверждённый факт посещения в демонстрационном сценарии |
| Отзыв | Оценка центра, необязательный текст и связь с посещённым занятием и записью |

Для запуска готовим 6–10 явно обозначенных демонстрационных площадок с полными карточками, фотографиями, занятиями, группами, ценами, расписаниями и начальными демонстрационными отзывами. Остальные существующие точки сохраняются в справочном каталоге с имеющимися сведениями. Неизвестная цена или оценка отображается как отсутствие данных.

Запись появляется у площадки после заполнения необходимых сведений и наличия подходящего сеанса. Даже если в прототипе заполнена карточка реальной организации, действие записи остаётся демонстрационным.

Для подробной карточки действует правило «одна строка — одна площадка по одному адресу». Старые многоадресные строки остаются справочными. При подготовке занятий конкретного филиала для него создаётся отдельная строка в том же региональном листе. Импорт связывает её с существующей точкой без дублирования метки.

Постоянные ID площадок, занятий и групп сохраняют связи после изменения названия и описания. Исходный способ объединения справочных точек и правила категорий берутся из design.md и [словаря проекта](../GLOSSARY.md); изменения подробного каталога не должны создавать повторные точки.

Основание: Q5–Q6, уточнения Q11, Q12, Q25–Q27.

## 3. Поиск, карта и карточки

### Точки входа и компоновка

Внутри map4child доступны три входа в раздел «Детские занятия»: переход из собственной поисковой строки, категория в интерфейсе карты и раздел «Занятия и группы» в карточке организации. Это элементы самостоятельного продукта; размещение в настоящем приложении Яндекс Карт в объём не входит.

Основной сценарий рассчитан на телефон: поиск сверху, карта и выдвижная панель результатов. На компьютере список находится слева, карта справа. Открытие и закрытие полной карточки сохраняет фильтры и положение карты. Сохраняются светлая, тёмная и существующая системная темы, переключение провайдера, кластеры и выбор точки при совпадении координат.

По уточнению пользователя от 11 ноября 2026 по умолчанию показан весь каталог, включая справочные площадки. Фильтр «Можно записаться» выключен; его включение оставляет площадки с подходящими свободными сеансами. Неполные сведения обозначаются явно.

### Правила фильтрации

- Карта и список показывают один набор площадок, соответствующий выбранным фильтрам.
- Основные фильтры сохраняются из исходной карты: «Специальность», «Тип партнёра», «Массовость», «Частный / государственный», «Район». Значения и счётчики берутся из соответствующих столбцов каталога с прежними правилами нормализации; отдельного фильтра по направлениям демонстрационных занятий нет.
- В каждом фильтре можно выбрать несколько значений: между ними действует «ИЛИ», между фильтрами — «И». Пустой выбор не ограничивает выдачу. Поисковая строка ищет по названию площадки.
- Возраст, дни недели, время и цена пробного занятия находятся в дополнительном свёрнутом блоке. Для совпадения одна конкретная группа должна удовлетворять всем заданным условиям этого блока и иметь подходящий свободный сеанс. Условия разных групп одной площадки не объединяются.
- При выборе нескольких дней достаточно подходящего сеанса в один из них. Временной интервал должен вмещать занятие целиком, включая его длительность.
- Цена измеряется в рублях за одно пробное посещение. Бесплатное пробное — 0 ₽. Неизвестная цена не равна нулю и не считается совпадением с ценовым ограничением.
- В краткой карточке показываются возраст, расписание и цена подходящей группы, а также рейтинг площадки. В полной карточке подходящие занятия стоят первыми; остальные можно посмотреть отдельно.
- Распознавание возраста и других фильтров из свободного запроса в первую версию не входит.

При отключённом фильтре «Можно записаться» справочные точки остаются доступны. Для заданных условий по занятиям требуется известное совпадение: отсутствие расписания не считается подходящим расписанием.

### Поиск рядом и провайдеры карты

Родитель выбирает точку поиском адреса или нажатием на карту. Для поиска рядом доступны радиусы 1, 3 и 5 км; значение по умолчанию после выбора точки — 3 км. Вариант «Вся карта» снимает ограничение радиусом. Расстояние рассчитывается по прямой. Маршрут открывается во внешних Картах.

Точки можно сохранить как «Дом» или «Школа». Для адресного поиска сохраняется введённый пользователем адрес; координаты из Яндекс Геокодера используются как временный кеш не более 30 дней по условиям API.

По умолчанию работает Яндекс Карта с сохранением существующего fallback на OSM. Поиск адреса через Яндекс Геокодер выполняется по нажатию «Найти» и используется с Яндекс Картой. В OSM точка выбирается нажатием на карту. При переключении на OSM результат Яндекс Геокодера не переносится на другую подложку: интерфейс предлагает выбрать точку заново. Остальные фильтры сохраняются; интерфейс явно сообщает, что ограничение радиусом ждёт новой точки.

Для адресного поиска требуется отдельно проверить доступ к Геокодеру. Наличие ключа JS API карты само по себе не подтверждает доступ к этому продукту. [Подключение Геокодера](https://yandex.ru/maps-api/docs/geocoder-api/quickstart.html). Ограничения кеширования и использования результатов на другой подложке описаны в пунктах 5.1.6 и 6.6.1 [условий API](https://yandex.ru/legal/maps_api/ru/); бессрочное хранение результатов Геокодера в LocalStorage не закладывается.

### Полная карточка

Карточка содержит адрес, фотографии и описание места; занятия и группы с возрастом и расписанием; программу, формат и преподавателя; рейтинг и отзывы; стоимость пробного посещения и абонементов. Для абонемента указываются количество занятий и срок действия. При отсутствии отзывов показывается соответствующее пустое состояние.

Основное действие — «Записаться на занятие». Для справочной площадки без нужных сведений объясняется, почему запись недоступна. Демонстрационные сведения обозначаются в карточке; демонстрационный характер записи явно указан на экранах записи и в «Моих записях».

Основание: исходные Must-have, Q2, Q8, Q10, Q13–Q14, Q17, Q27, Q29, Q31.

## 4. Расписание, запись и профиль

Доступные даты формируются из повторяющегося недельного расписания на ближайшие 28 дней по московскому времени. У группы заданы дни недели, время начала, длительность и количество пробных мест на каждый сеанс. Прошедшее время не предлагается для новой обычной записи. Праздничные исключения и разовые изменения расписания остаются за пределами первой версии.

Путь записи:

1. Выбрать занятие, группу и доступный сеанс.
2. Указать имя родителя, телефон и возраст ребёнка. При следующих записях поля подставляются из LocalStorage; возраст можно изменить для конкретной записи.
3. Проверить группу, дату, время, адрес, итоговую цену и порядок оплаты «в центре».
4. Подтвердить запись и сразу увидеть локальное подтверждение.

Возраст ребёнка должен соответствовать группе. Регистрация, имя ребёнка, отдельные профили детей и проверка телефона через SMS не требуются. Абонементы представлены справочно; запись выполняется на одно пробное посещение.

Число свободных мест изменяется только в этом браузере. Повторная активная запись на тот же сеанс блокируется. Перед окончательным подтверждением повторно проверяются локальная доступность и отсутствие дубликата.

В «Моих записях» доступны предстоящие, прошедшие и отменённые записи. При первом обычном открытии список пуст. После перезагрузки страницы контактные данные и записи сохраняются в пределах того же браузера.

До начала занятия запись можно отменить без штрафа после подтверждения действия. Отмена остаётся в истории и возвращает локальное место; после неё можно записаться заново. Для другой даты пользователь отменяет прежнюю запись и создаёт новую. После начала занятия обычная отмена недоступна.

Запись сохраняет сведения о площадке, группе, дате, адресе и цене на момент её создания. Снятие площадки с публикации не удаляет историю. Синхронизация записей между браузерами и фактическое резервирование мест у центров не выполняются.

Основание: Q1, Q5, Q7, Q12, Q15, Q26, Q32.

## 5. Посещение, отзыв и демонстрация

Наступление даты или окончание занятия само по себе не подтверждает посещение. Подтверждение выполняется отдельным действием в инструменте демонстрации. Только после него в приложении появляется предложение оставить отзыв.

Родитель оценивает центр от 1 до 5; текст необязателен. На одно посещение допускается один отзыв, который можно отредактировать или удалить. В отзыве указан посещённый вид занятия. Собственный отзыв появляется в карточке и учитывается в локальном рейтинге вместе с начальными отзывами из каталога.

В инструменте демонстрации есть действие «Создать пример прошедшей записи». Оно позволяет проверить цепочку без ожидания календарной даты: создать прошедшую запись → отдельно подтвердить посещение → получить запрос на отзыв → оставить отзыв и увидеть изменение рейтинга. Данные этого сценария сохраняются только в LocalStorage.

Подтверждение записи, результат отмены и запрос отзыва показываются внутри приложения. SMS, email и сообщения в мессенджеры не отправляются.

Основание: Q9, Q16, Q28, Q32.

## 6. Форма внутри Google Sheets

Редактор работает в большом окне таблицы. Сотрудник выбирает строку и открывает «map4child → Редактировать площадку» либо использует «Добавить площадку». Пользовательские формы внутри Sheets поддерживаются [Apps Script](https://developers.google.com/apps-script/guides/dialogs).

| Раздел формы | Поля и действия |
|---|---|
| Площадка | Название, адрес, координаты и исходные характеристики, описание, фотографии, признак демонстрационных сведений |
| Занятия | Добавить занятие; заполнить название, направление, программу, формат и преподавателя |
| Группы | Добавить группу к занятию; возраст, дни недели, время, длительность, пробная цена, абонементы, количество мест, активность |
| Отзывы | Начальные отзывы каталога; демонстрационные отзывы относятся к явно обозначенным демонстрационным данным |
| Проверка | Показать отсутствующие или некорректные сведения перед подготовкой к публикации |

Форма использует обычные поля, флажки, выбор времени и числовой ввод. Несколько занятий и групп добавляются кнопками. Сложная структура сохраняется программой в дополнительных служебных столбцах той же строки. Команда не редактирует JSON. Новые листы для сущностей каталога не создаются.

Все сотрудники с правом редактирования таблицы могут пользоваться формой и готовить карточки к публикации. Отдельные роли согласования в приложении не вводятся. Доступ к ручному запуску GitHub Actions определяется правами GitHub; право редактировать таблицу само по себе его не предоставляет.

Если другой сотрудник изменил карточку после её открытия, сохранение должно обнаружить конфликт и предложить загрузить актуальную версию. Чужие изменения не перезаписываются молча.

### Черновик и версия для публикации

- «Сохранить черновик» сохраняет незавершённую работу, не меняя версию для ближайшей сборки и текущий сайт.
- «Подготовить к публикации» проверяет поля и сохраняет готовую версию карточки. Форма сообщает, что она ожидает обновления сайта.
- Ручной запуск GitHub Actions публикует подготовленные версии. Несохранённые изменения формы и черновики в сборку не попадают.
- Работа над новым черновиком сохраняет предыдущую опубликованную карточку на сайте.

Состояния «черновик», «подготовлено» и «опубликовано» обозначают разные версии. Сохранение в таблицу не должно отображаться как успешная публикация на сайте.

### Фотографии

В форму добавляется только прямая ссылка на изображение и подпись к нему. URL сохраняется как ссылка; браузер показывает фотографию по этому URL. Загрузка файлов, общая папка Google Drive и копирование изображений при сборке не используются. Это уточнение пользователя от 11 ноября 2026 заменяет первоначальное требование загрузки файлов.

Ссылка должна быть доступна браузеру как изображение. Страница просмотра файла или веб-страница с фотографией внутри не гарантирует показ картинки; предпросмотр позволяет заметить ошибку. Недоступное изображение не должно ломать карточку.

### Снятие с публикации

Действие «Убрать с сайта» сохраняет данные площадки в таблице и исключает её из новой сборки после ручного обновления. Площадку можно вернуть без повторного заполнения. Аналогично отдельные занятия и группы можно сделать неактивными, сохранив саму площадку. Сохранённые пользовательские записи остаются в истории.

Основание: уточнения Q11 и Q18, Q19–Q26; по последнему ответу Q24 внешние изображения не копируются.

## 7. Подготовка данных и публикация

Поток публикации: форма Apps Script → Google Sheets → ручной GitHub Actions → проверка данных и сборка → gh-pages и GitHub Pages.

Существующий workflow расширяется чтением подготовленных подробных карточек со ссылками на изображения. Источник справочных точек и список региональных листов сохраняются. Финальные данные карточек и ссылки на фотографии публичны согласно [ADR о публикации данных](adr/0001-public-map-data.md).

Редактор может сохранять неполный черновик. Для подготовки подробной карточки к публикации нужны сведения, используемые её активными занятиями и группами: постоянные ID и связи, возрастные границы, расписание, длительность, цена пробного посещения и количество мест. Справочные записи продолжают обрабатываться по прежним правилам отсутствующих данных; неизвестная цена не подменяется нулём.

Сборка проверяет структуру, ссылки между объектами, уникальность ID, координаты и корректность активных групп. При ошибке чтения или проверки подготовленного каталога новая версия не публикуется. Для исходных справочных строк сохраняется действующее правило пропуска отдельных записей без корректных координат с отчётом о причине.

Автоматического запуска по расписанию, после редактирования ячеек или из кнопок формы нет. Обновление выполняется существующим ручным workflow. Успех определяется завершением deploy и проверкой сайта; коммит в gh-pages сам по себе его не подтверждает. При неуспешной публикации форма не должна показывать подготовленную версию как опубликованную. Новая версия становится видна при открытии или обновлении сайта.

Пользовательские контакты, записи и локальные отзывы не передаются в Sheets или GitHub. Исходные выгрузки, черновики, ключ сервисного аккаунта Google и другие серверные секреты не включаются в публичный результат. Базовые правила доступа и промежуточных файлов сохраняются из README и ADR.

Основание: окончательные ответы Q20 и Q23, Q24, Q30 и действующие правила исходного проекта.

## 8. За пределами первой версии

- Реальные записи в центрах, общий учёт мест и подтверждения центрами.
- Регистрация родителей, синхронизация между устройствами, отдельные профили детей.
- Онлайн-оплата и покупка абонементов.
- Самостоятельный перенос подтверждённой записи; используется отмена и новая запись.
- Автоматическое заполнение фильтров из запроса, контекстные рекомендации.
- Напоминания, отправка внешних сообщений и добавление в календарь.
- Видео занятий, расширенное портфолио преподавателя, дополнительные инструкции для посещения.
- Пользовательская функция даты актуализации сведений; служебные версии редактора нужны для подготовки и проверки публикации.
- Праздничные исключения расписания и индивидуальные изменения отдельных сеансов.
- Интеграция с интерфейсом настоящих Яндекс Карт, Pages CMS, дополнительные листы сущностей, автоматическая публикация.
- Диагностика ребёнка и карта развития из общей концепции проекта.

Основание: Q3, Q5, Q12, Q15, Q20, Q32–Q33 и уточнения по редактору.

## 9. Критерии приёмки

Критерии ниже описывают необходимые проверки будущей реализации. На дату подготовки спецификации их выполнение не проверялось.

### Сайт и поиск

| ID | Сценарий и ожидаемый результат |
|---|---|
| AC-01 | На чистом браузере открывается весь каталог: справочные точки и 6–10 полных демонстрационных площадок. «Можно записаться» выключен, отметки о демонстрации видны. Включение фильтра оставляет площадки со свободными сеансами |
| AC-02 | Переход из собственной поисковой строки, категория «Детские занятия» и раздел «Занятия и группы» в карточке организации ведут к соответствующей выдаче или занятиям |
| AC-03 | На телефоне доступны карта, поиск, панель результатов, фильтры, карточка и запись. На компьютере список расположен слева. После закрытия карточки сохранены фильтры и положение карты; светлая и тёмная темы читаемы |
| AC-04 | Доступны все пять прежних фильтров со значениями из столбцов таблицы. Выбор нескольких специальностей объединяет их выдачу; добавление района, типа партнёра, массовости и формы собственности сужает её. Справочные точки не требуют заполненных групп. Сброс возвращает весь каталог; карта и список показывают одинаковый набор. При дополнительных условиях «8 лет, начало с 19:00» центр с группами «8–10 лет в 17:00» и «12–14 лет в 19:00» исключается: условия должны совпасть у одной группы |
| AC-05 | Для окна 18:00–20:00 сеанс 19:00–20:00 подходит, а 19:30–20:30 исключается. При выборе двух дней достаточно совпадения одного. Бесплатное пробное соответствует 0 ₽; неизвестная цена не попадает в выборку бесплатных занятий |
| AC-06 | При выбранной точке переключение 1/3/5 км изменяет выдачу по расстоянию по прямой; «Вся карта» снимает радиус. «Дом» и «Школа» доступны после перезагрузки; маршрут открывается во внешних Картах |
| AC-07 | Поиск адреса работает с настроенным Яндекс Геокодером. Вызванный отказ карты включает OSM. Координаты ответа Геокодера на OSM не переносятся; можно выбрать новую точку нажатием. При недоступности обеих карт остаются список и карточки |
| AC-08 | Полная демонстрационная карточка показывает адрес, фото, описание, программу, формат, преподавателя, группы, возраст, расписание, пробную цену, абонементы с количеством занятий и сроком, рейтинг и отзывы. Подходящие занятия стоят первыми; недостающие справочные сведения не выдуманы |

### Запись и отзыв

| ID | Сценарий и ожидаемый результат |
|---|---|
| AC-09 | Для заданного недельного расписания создаются доступные сеансы в пределах ближайших 28 дней по Москве; время в прошлом не предлагается. После смены текущей даты диапазон обновляется без ручной правки таблицы |
| AC-10 | Родитель выбирает занятие, группу и сеанс, вводит имя, телефон и возраст, видит перед подтверждением дату, время, адрес, группу, цену и «оплата в центре». Подтверждение сразу создаёт локальную запись; возраст вне диапазона группы не проходит проверку |
| AC-11 | При одном локально свободном месте запись расходует его. Повторное подтверждение того же сеанса не создаёт дубликат, включая повторное открытие формы. Перезагрузка сохраняет запись и оставшееся количество мест |
| AC-12 | Отмена до начала требует подтверждения, переводит запись в отменённые и возвращает место. Повторная запись после отмены возможна. После начала обычная отмена недоступна |
| AC-13 | На первом открытии «Мои записи» пусты. Созданные записи, данные родителя и изменения возраста конкретной записи переживают перезагрузку. Предстоящие, прошедшие и отменённые записи различимы. После изменения или снятия площадки с публикации история содержит условия на момент записи |
| AC-14 | Создание примера прошедшей записи не открывает форму отзыва само по себе. После отдельного подтверждения посещения появляется запрос на отзыв. Простое наступление даты также не даёт права на отзыв |
| AC-15 | Оценка 1–5 сохраняется без обязательного текста, показывается с посещённым занятием и учитывается в локальном рейтинге. На посещение создаётся один отзыв. Редактирование и удаление корректно меняют список и рейтинг после перезагрузки |
| AC-16 | Запись, отмена и отзыв дают сообщения внутри приложения. Проверка сетевых запросов показывает, что контакты, записи и отзывы не отправляются центрам или в источники каталога; другой чистый браузер не получает эти локальные данные |

### Редактор и данные

| ID | Сценарий и ожидаемый результат |
|---|---|
| AC-17 | Сотрудник с правом редактирования Sheets открывает форму, создаёт площадку и добавляет не менее двух занятий с несколькими группами через поля и кнопки. Повторное открытие восстанавливает введённое; новые листы сущностей и ручное редактирование JSON не требуются |
| AC-18 | Для уже опубликованной карточки сохранение нового черновика не меняет версию для сборки. «Подготовить к публикации» проверяет активные группы и сохраняет готовую версию. Неполный черновик сохраняется, некорректная готовая версия отклоняется с указанием полей |
| AC-19 | Два сотрудника открывают одну версию карточки. После сохранения первым второму сообщается о конфликте; его сохранение не затирает чужие правки без предупреждения |
| AC-20 | Фотография добавляется прямой ссылкой с предпросмотром. Ссылка остаётся URL и загружается браузером напрямую; изображение не копируется при сборке. В форме нет загрузки файлов, Apps Script не запрашивает доступ к Drive. Ошибка внешнего изображения не ломает карточку |
| AC-21 | Добавленная подробная строка одного филиала существующей многоадресной организации дополняет нужную точку без дубля и без переноса его занятий на остальные адреса. Смена названия не разрывает связь с локальной историей |
| AC-22 | «Убрать с сайта» сохраняет данные в Sheets; после ручного обновления площадки нет в карте и поиске. Возврат восстанавливает карточку. Отключение отдельной группы исключает её из новой записи, сохраняя площадку и старую историю |

### Публикация и завершение

| ID | Сценарий и ожидаемый результат |
|---|---|
| AC-23 | Сохранение черновика, подготовка карточки и обычное изменение таблицы не запускают workflow автоматически. Форма различает сохранение и ожидание публикации. Один ручной запуск публикует подготовленные изменения вместе, сохраняя черновики вне сборки |
| AC-24 | Успешный workflow импортирует каталог, проходит проверки, собирает сайт, сохраняет результат в gh-pages и завершает deploy. После обновления публичной страницы видна подготовленная версия; новая запись в прототипе использует её условия |
| AC-25 | Ошибка чтения источника или проверки подготовленного каталога останавливает новую публикацию; предыдущий сайт доступен. Отдельная справочная строка без координат пропускается с объяснением по прежнему правилу. Ошибка deploy не обозначается как успешная публикация |
| AC-26 | В публичной сборке есть только предназначенные для сайта данные и изображения; отсутствуют ключ сервисного аккаунта Google, другие серверные секреты, исходные выгрузки, черновики и пользовательские контакты. Сайт продолжает работать как статическое приложение на GitHub Pages |
| AC-27 | Автоматические проверки проекта и сборка проходят после изменений. В браузере отдельно проверены поиск, полный путь записи, отмена и отзыв на мобильном и настольном размерах. Форма проверена в настоящей Google-таблице, публикация — настоящим workflow и по публичному URL; локальные проверки не заменяют эти результаты |

Минимальный набор данных для проверки должен содержать бесплатное пробное, неизвестную цену в справочной карточке, несколько групп одного центра с несовпадающими условиями, сеанс без мест, занятие за границей выбранного времени, справочную многоадресную строку и прошедшую запись без подтверждённого посещения. Это тестовые случаи, а не сведения о реальных поставщиках.

## 10. Условия реализации и порядок проверки

До проверки живого сценария нужно обеспечить доступ редакторов к таблице и Apps Script, а также проверить активацию Яндекс Геокодера. Это настройки интеграций; они ещё не выполнены в рамках данной спецификации. Существующие доступы проверяются перед изменением, повторные разрешения запрашиваются только при необходимости.

| Этап | Проверяемый результат |
|---|---|
| Контракт каталога и импорт | Справочные точки сохранены; подробные карточки, расписания, стабильные ID, версии и ссылки на изображения проходят проверки AC-18, AC-20–AC-22, AC-25–AC-26 |
| Форма Sheets | Редактор создаёт и меняет карточку без кода; черновик, подготовка, конфликт правок и работа с фото проверены по AC-17–AC-20 |
| Пользовательский прототип | На согласованном демонстрационном каталоге выполнены AC-01–AC-16 |
| Публикация и приёмка | Выполнены AC-23–AC-27; приложены фактические результаты команд, ссылки на workflow и проверенную публикацию, замечания ручной проверки |

Прототип готов к приёмке, когда выполнены критерии сайта, редактора и живой публикации. Если доступ к одной из интеграций ещё не настроен, соответствующие критерии остаются невыполненными и явно перечисляются в отчёте.
