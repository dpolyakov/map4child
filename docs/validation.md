# Проверки перед первым push

Обновлено 4 ноября 2026 года. Локально работают OSM и Яндекс; сначала SDK Яндекса возвращал `403 Invalid api key`, позднее загрузился без замены ключа. Причина нестабильности не установлена. Ниже результаты разделены по этапам.

## Gravity UI и две карты — 4 ноября

- Интерфейс переведён на Gravity UI UIKit 8: темы, шапка, селектор карты, кнопки, поиск, чекбоксы, карточки и диалог фильтров. Компоновка использует `Flex`; page-constructor не подключён.
- OSM — начальный выбор. Проверены живые тайлы и кластеризация 1615 точек через Leaflet; повторного импорта и дополнительной подготовки данных не было. Переход порядка координат выполняется только в адаптере карты.
- Проверены раскрытие большого кластера, список шести площадок с одинаковыми координатами, карточка и ссылки с `target="_blank"` / `rel="noopener noreferrer"`. Район в карточке отсутствует.
- Пересечение «Мульти» и «Хорошёво-Мнёвники» дало 135 точек. Проверены поиск одной площадки, пустая выборка, сброс и закрытие карточки, исключённой фильтром.
- При реальном отказе SDK Яндекса приложение перешло на OSM и показало уведомление; Console содержала этап и причину без ключа. После fallback сохраняется OSM. При следующем открытии OSM скрипт Яндекса не загружается.
- Позднее в том же прогоне Яндекс успешно загрузился. Проверены его подложка, метки, карточка, светлая и тёмная темы, сохранение выбора после перезагрузки и ручной возврат на OSM. Изменений ключа со стороны агента не было; успешная загрузка не объясняет прежний `403`.
- На 1280×800 и 390×844 проверены компоновка, селектор в шапке, темы 🖥️ / ☀️ / 🌙, мобильный диалог и карточка. Тёмная подложка OSM использует CSS-фильтр. Исправлен конфликт стилей Leaflet, смещавший числа кластеров от центра.
- `npm run check`: TypeScript и 34 теста прошли. `npm run build` и проверка состава `dist` прошли; сборка live-каталога больше не требует ключа Яндекса. Синтетический тест проверяет этот сценарий.
- Снимки сохранены локально в `.local/qa-gravity-osm-mobile.png`, `.local/qa-gravity-yandex-mobile.png` и исключены из Git. Проверка отказа загрузки тайлов самой OSM не выполнялась; прежние тесты загрузчика Яндекса продолжают проверять тайм-аут, сбой модуля и повторную попытку.
- Перед публикацией выполнен повторный импорт: 1615 точек, у 1113 есть ссылки-источники. В столбцах источников не найдено URL, скрытых только форматированием; текущий импорт не теряет такие ссылки. У 502 точек массив источников пуст. Блок «Источники» перенесён выше характеристик карточки, чтобы ссылки были видны без прокрутки длинного описания; отсутствие ссылок теперь обозначается явно.
- Lock-файл переведён с корпоративного зеркала на `registry.npmjs.org`, добавлен `.npmrc`. Чистая установка `npm ci` из публичного registry в отдельном каталоге прошла; секреты и URL исходной таблицы в отправляемых файлах не найдены.

## Темы и диагностика загрузки — 4 ноября

- `npm run check`: TypeScript и 34 теста в четырёх файлах прошли. `npm run build` и проверка состава `dist` прошли на прежнем каталоге из 1615 точек; повторного импорта не было.
- В браузере проверены светлая и тёмная темы, сохранение каждой после перезагрузки, возврат к режиму «Как в системе», карточка и диалог фильтров. Проверены мобильная ширина 390 и обычный экран 1280 пикселей, а также читаемость кнопки «Фильтры» при наведении в обеих темах.
- Причина отсутствия карты локализована до основного скрипта SDK: прямой запрос с текущим ключом и Referer `http://localhost:4173/` или `http://localhost:4174/` возвращает `403 Invalid api key`. Проверено, что Vite и Node используют одинаковое значение ключа и текущая сборка содержит именно его. Ключ не выводился в логи и отчёты.
- Теперь ошибки SDK, ожидания готовности, React-модуля и кластеризатора выводятся в Console с префиксом `[map4child]`, этапом, причиной и стеком. Ключ скрывается. Кнопка повторной загрузки делает новую попытку, ранее отклонённый Promise больше не кэшируется.
- Тесты загрузчика проверяют сетевой отказ и повторную попытку, тайм-аут и очистку скрипта, общую успешную загрузку, отказ React-модуля с сокрытием ключа и отсутствие ключа. До исправления тест повторной попытки падал; после исправления проходит.
- Сама подложка и её смена темы в этом прогоне не подтверждены: для проверки требуется устранить отказ ключа на стороне Яндекса. Интерфейс и резервный список работают; ошибка видна в Console при каждой неудачной попытке.

## Выполнено локально — 3 ноября

- `npm run check`: проверка TypeScript и 28 тестов в трёх файлах прошли.
- Проверены несколько координат в записи, объединение между листами, разные названия на одинаковых координатах, стабильность идентификаторов, строгий enum массовости и отдельная категория «Мульти».
- Проверены пропуски ошибочных строк, остановка при изменившейся структуре и пустом каталоге, блокировка демоданных в обычной сборке, требование ключа карты для live-каталога и удаление старого локального каталога при неудачном импорте.
- `npm run data:demo` и `npm run build:demo` прошли. Также выполнена сборка с явно тестовым значением ключа, чтобы проверить упаковку полного кода SDK и динамического кластеризатора; это не проверка работы API.
- Скрипты импорта и сборки читают `.env` и необязательный `.env.local`. После добавления ключа выполнена сборка демо; в браузере подтверждена передача ключа при загрузке SDK, само значение в отчёты не выводилось.
- `check-dist` проверил состав сборки; Google-клиент и конфигурация источника в браузерный код не включены.
- Workflow прошёл `actionlint 1.7.12`. Действия GitHub закреплены по SHA официальных репозиториев. Workflow не запускался.
- Браузер: обычный экран 1280×720 и мобильный 390×844. Проверены выбор специальностей по ИЛИ, пересечение с районом, поиск по названию без учёта регистра, пустая выборка, сброс, закрытие исключённой фильтром карточки, мобильный диалог и карточка «Мульти» с массовостью «Нет данных».
- Ссылки карточки имеют `target="_blank"` и `rel="noopener noreferrer"`; район в карточке не показан. Во время проверки ошибок и предупреждений в консоли браузера не обнаружено.

## Проверка с настроенными ключами — 3 ноября

- `npm run data:sync` успешно прочитал пять согласованных листов сервисным аккаунтом Google. Обработано 1609 строк, подготовлено 1615 точек; несколько координат одной строки дают отдельные точки. Объединённых дублей в этой выгрузке нет.
- Пропущены 15 строк без координат: 12 на листе «Хорошево-Мневники (не финал, в работе)» и 3 на листе «Коммунарка». Номера строк находятся в локальном `.generated/report.md`; исходная таблица не изменялась.
- `npm run build` и проверка состава `dist` прошли с настоящим каталогом. Финальный JSON занимает около 783 КБ, около 153 КБ после gzip.
- SDK с тем же ключом вернул `403 Invalid api key` для Referer `127.0.0.1` и `200` для `localhost`. Карта проверялась через `http://localhost:4173/map4child/` (dev) и `http://localhost:4174/map4child/` (собранная версия).
- В браузере загрузились подложка, цветные метки и кластеры. Нажатие на кластер из 857 точек увеличило масштаб и разделило его на меньшие группы. Группа из шести записей с одинаковыми координатами открыла список выбора; из него открылась карточка.
- Исправлено перекрытие областей нажатия: при смещении кнопки метки её прежняя область в обёртке SDK перехватывала клики по соседним кластерам. Абсолютное позиционирование кнопок убрало эту область. Повторная проверка попадания в центр кластера и нажатия прошла в dev и собранной версии.
- На экране 1280×800 проверены поиск, карточка, ссылки и пересечение специальности «Мульти» с районом «Хорошёво-Мнёвники» (135 точек). Исключённая фильтром карточка закрылась. На 390×844 проверены диалог фильтров, поиск одной площадки и мобильная карточка поверх карты.
- В консоли собранной версии ошибок и предупреждений не обнаружено. Снимки проверки сохранены локально в `.local/qa-live-preview.jpg` и `.local/qa-live-mobile.jpg` и исключены из Git.

## Граница проверки

- Географическая точность координат и содержание строк в этом прогоне не проверялись. Импорт и интерфейс используют данные таблицы; автоматического геокодирования нет.
- Работа ключа на домене `dpolyakov.github.io` ещё не проверена. Локальная проверка на `localhost` не подтверждает настройку домена публикации.
- На момент локальных проверок push, GitHub Actions и публикация Pages ещё не выполнялись. Пользователь разрешил первый push и публикацию после проверок 4 ноября; результаты публикации будут зафиксированы отдельно.
- `example.html`, `.generated/`, `.local/`, `dist/`, `.env`, `.env.local` и `node_modules/` исключены из Git. Тестовые примеры содержат вымышленные записи. Финальные публичные данные будут находиться только в собранном сайте в `gh-pages`.

Для публикации нужно настроить CI-переменные, Google Secret и Pages Source согласно [README](../README.md), затем отдельно проверить реальный workflow и опубликованную карту.
