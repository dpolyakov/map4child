# Подробные карточки в репозитории

Решение согласовано 12 ноября 2026 года и реализовано для демо. Google Sheets остаётся источником справочных меток; подробности десяти выбранных площадок и фотографии редактируются в Git. Для этой итерации не нужны CMS и форма Sheets. Этот порядок заменяет требования к редактору для демонстрационного набора из [спецификации MVP](mvp-spec.md), но не меняет импорт остальных меток.

Первые восемь площадок остаются вымышленными, без привязки к реальным организациям. Их ID, содержание, группы, цены и отзывы сохранены; URL фото заменены локальными путями. В двух новых карточках сведения и фотографии взяты с официальных сайтов. Отзывов и платных абонементов для них не придумано.

## Схема

Одна площадка — один файл `content/venues/<id>.json`. Изображения лежат в `content/venue-media/<id>/`. Контракт и проверка: [marketplace-model.ts](../shared/marketplace-model.ts).

| Поля | Назначение |
|---|---|
| `id`, `name`, `address`, координаты, категории | Постоянная идентичность и метка |
| `legacyIds` | ID исходной метки, которую заменяет подробная карточка; без нечёткого поиска по названию |
| `demo` | `true` для вымышленной площадки; `false` для сведений о реальном месте. Все записи в прототипе демонстрационные независимо от этого флага |
| `description`, `photos` | Описание и галерея; фото содержит `kind: "url"`, `url`, `alt` |
| `sources`, `sourceCheckedAt` | Первичные страницы, оригиналы фотографий и дата проверки сведений |
| `trainers` | Общая команда: ID, имя, краткое описание, `photo` с `url` и `alt` |
| `activities` | Программы: описание, формат, направление, группы, `trainerIds` команды направления |
| `teacher` | Прежний одиночный преподаватель старых моков; новые карточки используют `trainerIds` |
| `groups` | Возраст, активность, недельное расписание, цена пробного, число мест, информационные абонементы |
| `reviews` | Начальные отзывы; у новых реальных площадок пустой список |

Локальная ссылка на фото имеет вид `venue-media/gymkids-profsoyuznaya/hall-1.jpg`. Путь проверяется, файл должен существовать внутри `content`; при сборке он копируется в публичные ресурсы. Загрузка фотографий с внешних сайтов при сборке и показе этих карточек не требуется.

ID площадок, занятий и групп не меняют при редактировании: на них ссылаются записи в LocalStorage. Для новой реальной площадки в `legacyIds` добавляют точный ID её справочной метки. GYMKiDs и FLY ZONE заменяют разные метки, даже при совпадении координат. По снимку таблицы от 11 ноября они находятся в строках 6 и 5 листа «ЮЗАО (Беляево/Коньково/Чертаново)», район «Беляево».

Карточка из репозитория имеет приоритет над `M4C_READY` с тем же ID. Удалять старые копии восьми моков из таблицы не требуется. Другие подробные строки Sheets продолжают обрабатываться по прежним правилам.

## Что подтверждено источником

Данные проверены 12 ноября 2026 года по [сайту GYMKiDs](https://msk-profsoyuz.gymkids.ru/), [каталогу сети](https://gymkids.ru/clubs/moscow), [странице Fly Zone на Профсоюзной](https://fly-z-one.ru/na-profsouznoi) и [сайту паркура](https://parkour-konkovo.fly-z-one.ru/). Это сведения, опубликованные организациями; текущий набор и наличие мест напрямую не подтверждались.

Обе площадки заявляют бесплатное пробное занятие; платные цены предлагается уточнять. Длительность паркура 50 минут указана в [описании услуг от 10 апреля 2024 года](https://parkour-konkovo.fly-z-one.ru/page47837155.html). В программе паркура «14+» демонстрационная группа ограничена 14–17 годами в соответствии с возрастным диапазоном прототипа.

Сайты не публикуют доступные сеансы и назначения тренеров. Поэтому расписание, свободные места и статусы записи условные и отмечены в интерфейсе. В каждой программе показана команда соответствующего направления; это не назначение всех тренеров на занятие. Тренеры воркаута не включены в паркур.

## Редактирование и сборка

После изменения JSON или фотографий выполните из каталога проекта:

```sh
npm run check
npm run build
npm run preview -- --host localhost --port 4175
```

`build` заново объединяет текущие файлы с последним локальным снимком `.generated/raw.json`. Google и сайты площадок при этом не вызываются. Для первого получения или обновления справочных меток нужен `npm run data:sync` с доступом к Google. Ошибка схемы, отсутствующее фото или конфликт идентичности останавливают сборку.

Полностью без Google можно собрать отдельный демонстрационный каталог:

```sh
npm run data:demo
npm run build:demo
npm run preview -- --host localhost --port 4175
```

Он содержит десять подробных карточек и шесть синтетических справочных точек. `data:demo` заменяет локальный снимок; для возврата к полной карте выполните `data:sync`. Обычная команда `build` запрещает публикацию каталога в режиме `demo`. Для dev после правки файлов повторите `data:demo` либо сборку, затем перезагрузите страницу. Адрес проверки: [localhost:4175/map4child/](http://localhost:4175/map4child/).

Публикация Pages по-прежнему запускается вручную. Push кода сам по себе сайт не обновляет; workflow продолжает читать метки из Google. Прежняя команда `data:seed-demo` для этого набора больше не нужна.

## Проверка 12–13 ноября 2026

- Типы и 64 теста прошли; проверены приоритет файлов, точная связь двух меток, локальные фото, ссылки на тренеров и запись с возрастом 1,5 года.
- Обычная сборка полного каталога, автономная `data:demo` → `build:demo` и сборка прежнего Apps Script прошли. Полная карта проверялась на локальном снимке Google от 11 ноября: 1545 точек, десять подробных карточек; свежий импорт Google не выполнялся.
- В браузере проверены фильтр десяти доступных карточек, программа и команда каждой новой площадки, полный путь записи GYMKiDs, восстановление после перезагрузки, быстрая запись FLY ZONE и отмена обеих записей. Использовались вымышленные контактные данные.
- Проверены размеры 390×844 и 1280×900, локальные фотографии и работа Яндекс Карт. Живой workflow и публичная страница после этих изменений отдельно не проверялись.
